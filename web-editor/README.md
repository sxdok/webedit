# Web 可视化编辑器（文档模式 + Web 模式）

布局与交互参照 **Qt Designer** 的四区结构，支持两种编辑模式，**两套内容独立保存、切换零丢失**：

| 模式 | 画布 | 布局方式 | 组件 |
|---|---|---|---|
| `document` 文档模式 | 真实物理尺寸纸张（默认 A4 210×297mm @96DPI = 794×1123px） | 文档流（纵向数组） | 通用 + 文档专用 |
| `web` Web 模式 | 设备画布（Desktop/Laptop/Tablet/Mobile/自定义） | 绝对定位 `frame{x,y,w,h,rotation}` + 容器嵌套 | 通用 + Web 控件/容器/展示 |

技术栈：**React 18 + TypeScript（strict）+ Tailwind CSS 3 + Zustand 5 + Vite 6**，图标用 `lucide-react`，
不引入任何重型 UI 库；拖拽用原生 Pointer/HTML5（不引入 dnd-kit/react-dnd）。

## 一、运行

```powershell
# ① 日常使用：先构建，再用启动脚本托管（推荐，静态服务不需要子进程权限）
cd E:\可视化编辑器\web-editor
python 启动编辑器.py            # 托管 dist/，默认 5179，自动开浏览器
python 启动编辑器.py -p 8080    # 指定端口
python 启动编辑器.py -b         # 先 npm run build 再启动
python 启动编辑器.py -q         # 不开浏览器
python 启动编辑器.py -c         # 带 ?check=1 打开（跑自检）

# ② 开发：
npm run dev        # 开发服务器 http://127.0.0.1:5178（需要 esbuild 子进程权限）
npm run build      # 类型检查(tsc -b) + 打包到 dist/
npm run typecheck  # 只做类型检查
```

### URL 参数（可组合）

| 参数 | 作用 |
|---|---|
| `?check=1` | 运行自检（数据层 + 渲染层），结果写入标题、console 与右下角浮层 |
| `?diag=1` | 启动后打开诊断面板（日志 / 状态 / 环境） |
| `?demo=1` | 灌入示例文档（两种模式各一份样例内容） |
| `?mode=web` / `?mode=document` | 启动后切到指定模式 |
| `?log=debug|info|warn|error` | 控制台输出级别（内存缓冲始终全量记录） |
| `?theme=monokai` / `?theme=light` | 指定编辑器主题（也会记住在本地） |
| `?scroll=N` | 启动后把画布滚动 N px（调试吸顶/滚动类问题） |
| `?select=<类型>` | 启动后选中第一个该类型的节点（如 `?select=table`），用于核对属性面板排版 |
| `?cell=1,0[;1,1]` | 再选中该表格的这些单元格（行列从 0 起），用于核对单元格格式 |
| `?printdebug=1` | 打印时在纸面左上角渲染尺寸诊断块（排查分页/空白页） |
| `?spec=1` | 生成「组件与属性说明清单」并写到运行目录 `docs/`（无 `/__save` 接口时改为下载） |
| `?prefs=1` | 启动后打开「首选项」（编辑器设置集中在这里；截图/核对用） |
| `?load=<url\|路径>` | 载入一份已有 HTML（本工程导出的 HTML 能**原样读回**；等价入口：文件 →「打开 HTML…」/「从 URL 载入 HTML…」） |

> **本机沙箱注意**：`vite dev` / `vite preview` / `npm install` 都依赖 esbuild 启动子进程，
> 在 DSH 的受限文件沙箱下会报 `spawn EPERM`（沙箱边界，不是代码问题）。两种做法：
> ① 放宽权限运行（本会话已验证可行）；② 只用静态服务托管已构建的 `dist/`：
> `python -m http.server 5179 --bind 127.0.0.1 --directory dist`（无子进程，受限沙箱可用）。

打开 `http://127.0.0.1:5179/?check=1` 会跑一遍**数据层自检**：结果写入 `document.title`、
打印到 console，并渲染成右下角浮层（便于无头截图核对）。

> ⚠ **无头跑自检要用"真实时间"等它跑完**：自检靠一串 `setTimeout` 链（每段 200~260ms）+ 异步交互检查，
> 全程约 2.5 分钟。用 `msedge --headless --dump-dom --virtual-time-budget=…` 取标题会**在第一段
> `finish()` 就 dump**（那时只有 17 条，标题看着却是「17/17 全部通过」，很容易误判）。
> 可靠做法：`node logs/cdp-eval.mjs "http://127.0.0.1:5179/?check=1" logs/probe-selfcheck.js`
> （两个脚本都在 `logs/` 下、已 gitignore；轮询到标题稳定再返回，输出 `title` + 失败清单）。

## 三、关键设计

**1. 双模式零丢失**：`EditorDocument` 里 `document`（页面配置 + 组件数组）与 `web`（画布配置 + 根容器树）
是两套完全独立的数据；`setMode` 只改 `mode` 字段（并清空选中），切模式**不动任何内容**，且本身入历史栈可撤销。
store 内部用 `getForest(doc)` / `setForest(doc, forest)` 把两种布局统一成「森林」，
所以增删改移只写一份逻辑。

**2. 注册表驱动**：组件定义 `ComponentDefinition{type,label,category,supportedModes,icon,defaultProps,defaultFrame,propSchema,render}`。
左侧面板按 `supportedModes` 过滤并分组；右侧属性面板按 `propSchema` 的 `group` 分节、
按 `control` 派发控件。**新增组件 = 写一个文件 + 注册，不改面板与画布代码**。

**3. 所见即所得**：画布用 `def.render(props, ctx)` 渲染真实最终外观（真实 `<h1>`–`<h6>`/`<table>`/`<button>`…），
只有选中（2px #1677ff 描边）与悬停（1px 淡蓝）时才有编辑态外壳；`ui.preview` 可整体关掉编辑态。

**4. 缩放**：CSS `transform: scale()` + 外层容器宽高同步缩放后的尺寸（`ResizeObserver` 量真实高），
避免缩小时下方留白；切换模式时自动按「适应宽度」适配。

## 四、主题（浅色 / 深色 Monokai）

**首选项 → 外观 → 界面主题** 切换（原来视图菜单里也有一个开关，已按用户 2026-09-24 要求移除），或用 `?theme=monokai`。深色配色参考 Monokai：
底 `#1e1f1c`、面板 `#272822`、控件 `#34352c`、边框 `#3e3d32`、正文 `#f8f8f2`、
主色（青）`#66d9ef`、告警橙 `#fd971f`、成功绿 `#a6e22e`、危险粉 `#ff6188`。

范围说明（很重要，避免误解）：

| 你看到的东西 | 跟不跟主题 | 依据 |
|---|---|---|
| **编辑器外壳**：菜单栏 / 工具栏 / 左右面板 / 组件树 / 诊断面板 / 属性面板的所有控件 / 浮层 / 画布上的编辑态手柄与参考线 | **跟** | 颜色来自 `--ui-*` 令牌 |
| **画布内容**：纸张、Web 设备画布、组件渲染出的最终外观、**组件箱里的缩略图预览** | **不跟** | 那是"要打印/导出的成品"，颜色来自文档配置与 `props`；文档模式的纸始终是白的，缩略图也刻意固定白底纸张预览 |

- **写界面代码用语义类**（首选，两边自动都对）：`ui-bg` `ui-surface` `ui-raised` `ui-line` `ui-ink` `ui-ink-2` `ui-ink-3` `ui-accent`
  —— 定义在 `src/index.css` 顶部（由 `:root` + `html[data-theme='monokai']` 的 `--ui-*` 令牌驱动）。
  存量代码另外还靠**工具类重映射**兜底（`bg-white`、`text-gray-700`、`border-line`… 一条条列在 `src/index.css` 的 monokai 段）。
- ⚠ **坑 1（2026-09-23）**：`bg-gray-50/60`、`border-line/80` 这类**带不透明度**的工具类，Tailwind 生成的是**独立类名**
  （`.bg-gray-50\/60`），只写 `.bg-gray-50` 的规则**管不到**它 → 暗色下残留浅色底板。
- ⚠ **坑 2（2026-09-24）**：`hover:` / `disabled:` / `focus:` / `group-hover:` 同理都是独立类名
  （`hover:bg-gray-50`、`disabled:bg-gray-50`、`focus:border-primary`…），基础类覆盖了不等于变体覆盖了。
- ⚠ **坑 3（2026-09-24）**：`text-[#374151]` 这种**任意值类**根本不在重映射机制里 —— 属性面板的属性名/分组标题
  原来就是这么写的，暗色下对比度只有 1.47（几乎看不见）。已改成 `ui-ink-2` / `ui-ink-3`。
- ⚠ **坑 4（2026-09-24，用户反馈"深色主题下画布里的 Web 输入框变黑"）**：**画布内容也不该跟主题**，
  而重映射规则和"表单控件统一跟随主题"那条是**全局**的 —— 画布里的真 `<input>` 照样被涂黑。两道修：
  1. 表单控件规则排除画布：`input:not(#canvas-viewport input):not([data-comp-thumb] input)`（select/textarea 同理）；
  2. **进了画布就把整套主题令牌还原成浅色**（`html[data-theme='monokai'] #canvas-viewport, [data-comp-thumb] { --mk-surface:#fff; --mk-ink:#1f2329; … }`）——
     因为所有重映射规则写的都是 `var(--mk-*)`/`var(--ui-*)`，自定义属性按继承就近取值，所以组件内部即使用了
     `bg-white` / `border-line` / `text-gray-700` 这类被重映射的类，在画布里也解析回浅色。
     ★**新增重映射规则时只准用令牌、不要写死颜色**，否则这里还原不到（`npm run audit:dark` + 下面那条自动审计会盯着）。
- **两道检查**（改外壳样式必跑）：
  1. 源码级：`npm run audit:dark` —— 扫全部外壳源码，列出"用到但没被暗色重映射覆盖"的颜色类（退出码 1 = 有漏项），
     并单独报"任意值颜色类"；
  2. 运行时：`?check=1` 里的**「暗色模式自动审计」**断言 —— 切 Monokai 后把**全部 47 个组件**逐个加进画布、选中、
     展开所有属性分组，连同左侧组件箱与「首选项 / 新建文档 / Markdown / 诊断」四个浮层一起遍历 DOM，
     判据是"外壳里没有浅色底板、没有对比度 < 2.0 的文字"（自动排除 `#canvas-viewport` 与 `[data-comp-thumb]`）。
- 另有 4 条「暗色主题」断言：首选项各分组的**对比度 ≥ 3 且底板够深**、分组底板不再是浅灰、Markdown 源码区深底浅字、
  组件缩略图**仍是白底纸张预览**（不跟着变暗）；跑完会把主题还原成浅色。
- ⚠ **写这类视觉断言的两个坑（2026-09-24 真踩过，都是测试环境假象、不是产品问题）**：
  1. **无头 + `--virtual-time-budget` 下 CSS 过渡不推进** —— 带 `transition-colors` 的元素会**停在切主题前那一刻的颜色**上，
     于是整片"深底配浅色字"的假失败（第一版报了 39 处，而诊断里 CSS 变量和各色探针全是对的）。审计期间要临时注入
     `*{transition:none!important}`（自检里的 `freezeAnim()`）；
  2. **要排除"颜色本身就是内容"的元素**：取色器色板 `[data-color-swatch]`（那一格的背景就是它代表的颜色，白色板当然是白的）、
     组件缩略图 `[data-comp-thumb]`、画布 `#canvas-viewport`。
- 外部插件提醒：插件渲染的是**画布内容**，颜色照 `props` 写即可；只有插件额外画**浮层/编辑态装饰**时，
  才需要用上面的语义类。

### 大文档与浏览器本地存储（2026-09-24 修：QuotaExceededError 把编辑器写崩）

**现场**：用户打开一份 7.2MB 的 `.json`（9 个节点里 **5 张图内嵌 base64**，`image` 的 props 合计 7.06MB）→
localStorage（约 5MB/源）写不下 → `setItem` 抛 `QuotaExceededError` → 错误落在 **store 更新的渲染路径**上
（现场堆栈：`setDocPageCount` → persist → quota）→ 被错误边界抓住，弹「编辑器渲染出错」。
"打开这种 JSON" 本身就是一次 store 更新，于是**打开即炸**。

**修法（三件，都在"别把内嵌图写进本地存储"这条线上）**：

1. `store/persistStorage.ts`（新）：**配额安全存储** ——
   · 单次 payload 超过 **3.5MB 预算**就**跳过写入**（内嵌 base64 图片不进 localStorage），
   · 真写了被浏览器拒绝也**不抛**（`try/catch` + 事件通知）；
   · 两种情况都派发 `editor:persist-overflow`，并记一笔供诊断/自检读取（`lastPersistOverflow()`）。
2. `partialize` 里**当前页的 doc 不再存第二份**（当前页槽位放占位空壳，恢复时由最新的 `doc` 覆盖）——
   payload 直接砍半（7MB 文档从 ~14MB → ~7MB），单页文档是最常见情形。
3. `components/layout/NoticeBar.tsx`（新，全局提示条）：底部提示条（`[data-persist-overflow]`）——
   「约 X MB，超过浏览器本地存储上限，**没有自动保存**（文档还在，编辑不受影响）；要留住改动请用
   **文件 → 导出 JSON** 存到磁盘」+ 关闭按钮。同一根提示条也承接**导入结果**（见下节）。

**结论与用法**：打开大文档**不再报错**，内存里照常编辑导出；localStorage 保持上一次成功保存的内容不变（不会被写坏）。
大文档（内嵌图片）的正路是**文件**（导出 JSON / HTML / .docx / PDF），不是浏览器自动保存。
想让自动保存也装得下，就把图片换成外链或先压小（MCP 的 `asset.embed` 单文件上限 20MB，建议先压图再说）。

### 把导出的东西读回来：多条入口、一份逻辑（2026-09-24 补「导出的 html 没有地方导回打开」）

| 入口 | 操作 | 格式 | 说明 |
| --- | --- | --- | --- |
| 菜单 | 文件 → **打开 HTML（导入成组件）…** | `.html/.htm` | 弹文件选择框 |
| 菜单 | 文件 → **打开（JSON）** | `.json` | 编辑器「保存（导出 JSON）」的存档 |
| 菜单 | 文件 → **从 URL 载入 HTML…** | http(s) / 站内相对路径 | 跨域地址需对方允许 CORS |
| **拖拽** | 直接把文件**拖进窗口**（任意位置松手） | `.html/.htm/.json` | 松手前给一层「松手导入」提示；拖组件用的是自定义 MIME，不会被误接管 |
| URL | `?load=<地址或站内路径>` | `.html` | 截图 / 无人值守用 |

- 这些入口共用 `utils/importDocument.ts`（`importHtmlIntoEditor` / `importJsonIntoEditor` / `importFileIntoEditor`），
  统计口径、提示文案、失败原因**永远一致**，不会两条路两种行为；
- 导出的 HTML **自带 `data-node-type`**，原样读回能还原组件类型（标题层级 / 列表条目 / 表格数据 / 目录条目都对得上）；
  外部页面也能导，认不出的标签计进 `skipped` 并在提示里列出来；
- 结果统一走 `NoticeBar`（`data-notice-bar`）：成功给「顶层 N 个 / 共 N 个组件」+ 识别明细（精确 / 猜的 / 跳过）；
  失败给**可行动的原因**（如「打开失败：缺少 document 和 web 字段（实际顶层字段：a）」），不是干巴巴一句"导入失败"；
- 拖拽实现只在 `dataTransfer.types` 含 `Files` 时接管（捕获阶段 `preventDefault`，挡掉浏览器"直接打开那个文件、把编辑中的文档顶掉"的默认行为）。

## 五、打印 / 导出

### 打印（`文件 → 打印…`，或 Ctrl+P）

打印分页采用**已验证产线（`江苏誉创_金卫智慧舱_AGV方案_V5.0.html`）同款做法**：

```css
@page { size: <当前纸张>; margin: 0 }        /* 由 App.tsx 按当前文档注入（Chrome 不解析 @page 里的 var()） */
.sheet/[data-paper] { width:210mm; height:297mm; padding:<文档页边距>; overflow:hidden }   /* 屏幕样式不变 */
@media print {
  [data-paper] { margin:0; box-shadow:none; break-after: page; page-break-after: always }
  [data-paper]:last-child { break-after: auto }        /* 末张不强制分页 */
  .no-print { display: none !important }               /* 菜单栏/面板/状态栏/标尺/网格/辅助线/手柄/高亮/说明 */
}
```

- 纸张保持物理尺寸（297mm）与内边距，**页脚/页眉用绝对定位钉在纸底**，所以打印出来的页码位置与屏幕一致；
- 打印时额外做两件事：`print-color-adjust: exact`（否则 Chrome 不打印背景色，柱状图/表头底色会消失）、
  去掉 `.node-selected/.node-hover`（选中高亮是编辑器态，不能印进纸里）；
- ⚠ **打印设置必须是：纸张 A4、缩放 100%、边距「无/默认」、勾选「背景图形」**。
  画布下方有一行同样内容的提示（不打印）。若边距选了"默认/1cm"，可打印区只有 ~277mm < 297mm，
  浏览器就会把每张纸挤出一页空白 —— 这不是编辑器的问题（同一套 CSS 的 V5.0 文档实测打印正常）。
- **想完全不依赖打印设置**：用「文件 → 导出 HTML」拿到自包含的单文件 HTML，
  它用 `@page{margin:<文档页边距>}` + 内容流，打印时由浏览器自己分页，任何边距设置都正确。

排障开关 `?printdebug=1`：左上角渲染诊断块（纸张/容器 `display/height/margin/break-*`），打印时会带到 PDF。

### 右侧属性面板：紧凑列表 + 分组折叠 + 悬停气泡

属性面板是**两列列表**（左列固定宽度的属性名，右列控件），一行一个属性：

- **属性名过长只显示主名**：schema 里写成 `数据（每行一条，用 | 分列）` 这种「主名（填写说明）」形式时，
  列表里只显示 `数据`；**说明默认全部隐藏**，鼠标移到属性名上弹**气泡**显示完整说明
  （`ui/Tooltip.tsx` 自带实现，`position:fixed` 定位所以不会被面板的滚动容器裁掉；不用原生 `title`）；
  属性名下方有**虚线下划线**作为"这里有说明、可以悬停"的提示；
- **宽控件改两行式**：`textarea / richtext / spacing / edge / frame / children / cells / tableSize` 独占整行
  （属性名在上、控件在下），避免被挤窄；
- **分组折叠**：`表格 / 单元格 / 内容 / 排版 / 外观 / 尺寸 / 布局 / 高级`，**默认只展开「表格」**（表格组件）或
  「内容」；分组标题悬停同样弹气泡解释该组含义；
- **表格的"整体属性 vs 单元格属性"分得很清楚**（刻意这样设计）：
  - **「表格」组** = 整张表的属性：数据、行/列数量与增删、表题、表宽、列宽、行高、线条风格、边框、表头底色…
    以及作为**默认值**的 内边距 / 对齐 / 字号（标签里写明"（默认值）"）；
  - **「单元格」组** = 只作用于画布上**选中的单元格**：底色 / 字色 / 字号 / 加粗 / 对齐 / 内边距 + 清除；
    **选中单元格时该组自动展开**（否则用户点了格子却找不到格式控件），取消选中后回到默认折叠；
  - 分组标题的气泡直接把关系讲清楚：「表格」组写着"下面「单元格」组里针对个别格子的设置会覆盖这里的默认值"，
    「单元格」组写着"没被覆盖的项沿用「表格」组的默认值"。

面板的每一行都带 `data-prop-row` / `data-prop-label` 标记，**自检会遍历全部组件逐个检查**
（不溢出、属性名不折行、单行式行高不超标），见下一节的自检条目。

**面板顶部的「组件 ID」**（`data-props-head` / `data-props-id` / `data-copy-id`）：

- 显示的就是节点的 `node.id`（用户 2026-09-24 要求：是组件 ID 就放在 `type` 标签**后面**，别再单独占一行）；
  悬停气泡写明"本文档内唯一、写进文档 JSON、选中/撤销重做/组件树/MCP 的 `node.*` 都用它"，右侧一个复制按钮；
- **ID 形状**：`类型前 3 个字母_10 位随机`（如 `toc_fe775e9026`、`bul_ea1ea2bcd9`），由 `utils/id.ts` 的 `createId()` 生成
  （`crypto.randomUUID()` 截 10 位，退化到 `Math.random()`）；
- **唯一性**：随机空间约 40 bit，实测示例两页 180 个节点（含嵌套）零重复；**并且读档/导入时会强制兜一道** ——
  `treeUtils.normalizeDoc()` 把"缺失 ID / 重复 ID"的节点重新生成 ID（首见保留），这样手工改过的 JSON、
  老存档、外部通道写进来的文档都不会出现"选一个选中俩 / 改一个动两个"。复制组件走
  `cloneSubtreeWithNewIds()`，整棵子树换新 ID。以上都有自检断言钉住。

### 图片：一行一张图（一个组件，没有"单图/多图"两个字段）

2026-09-23 用户要求：图片组件**只有一个图片入口** —— 默认就是一行，行尾一个 **＋**。
属性面板里就是这个行编辑器（`imageRows` 控件），没有单独的「图片（单图）」与「多图」：

| 操作 | 效果 |
|---|---|
| 默认 | **1 行**（行首写「图片1」，两个输入框：地址 / 图题） |
| 行尾 **🖼** | 选本地图片文件 → 读成 `data:URL` 填进**这一行**的地址 |
| 行尾 **＋** | 在这行**下面**再加一行一样的图片行（行首变「图片2」，再点就是「图片3」…） |
| 行尾 **−** | 删掉**这一行**（只剩 1 行时禁用，不会删空） |
| 上限 | **最多 5 张**：到 5 行后 ＋ 变灰 |
| 「列数」（1~5） | 多张时并排几列（1 列 = 一张一行，垂直排下去） |

- 存储仍是 `props.images` 多行文本（每行 `地址 或 地址 | 图题`）→ MCP、HTML 导入、老文档都不受影响；
- 空行不渲染（行编辑器里刚加出来的空行不会画到纸上）；
- ⚠ 踩过的坑：**行数只由换行符决定**（`parseRows` / `joinRows` 严格互逆）。不能"trim 一下看着是空的就当一行"——
  那样"全空的占位行"会被压成一行，表现就是**「没填地址时点 ＋ 加不出行」**和
  **「删掉上面一行后下面的行全没了」**（用户 2026-09-23 报的两个 bug，同一个根因）。
  同理图题**不能连尾部空白一起 trim**：值要在"输入框 → props → 再解析回输入框"之间往返，
  尾部被吃掉的话用户敲 "图 1-1" 的空格当场就没了；
- **老文档兼容**：老的单图写法 `props.src` + `props.caption` 照常渲染，面板里会把它**当作第 1 行显示**，
  一旦在这里编辑就自动迁移进 `images` 并清掉 `src`/`caption`（同一张图，不会存两份）；
- 多张时「整组图题」（`caption`）才会出现在「排版」组里（单张时那张图的图题就写在行里）；
- 早期的「并排双图」（`imagePair`）**保留但已从左侧面板隐藏**：老文档照常渲染/编辑，新文档请用「图片」。

### 要点列表：行首缩进 = 子要点（`bullets`）

「要点列表」的**子要点**靠**行首缩进**分级，一个级别 = **2 个半角空格 / 1 个 Tab / 1 个全角空格**
（中文输入法按空格打出来的就是全角 U+3000，一样认），最深 3 级：

```
第一条要点            → • 第一条要点
  子要点一（2 空格）   →   ○ 子要点一（缩进一级，符号换空心圆）
	Tab 子要点          →   ○ Tab 子要点（Tab 也算一级）
　全角空格子要点        →   ○ 全角空格子要点（全角空格也算一级）
    更下一级（4 空格）  →     ▪ 更下一级（二级）
```

- 符号按级变"轻"：**• → ○ → ▪**（方形是 ▪ → ▫ → •，对勾/短横各级同形）；
- 勾「使用编号」时按级编号：**1. → 1.1. → 1.2. → 2.**（子级不会把父级编号推进）；
- ⚠ 踩过的坑：解析**不能用 `shared.lines()`** —— 它每行都 `trim()`，行首空格全被吃掉，
  级别恒为 0，**子要点从来没生效过**（用户 2026-09-23 报「bul_xxx 组件的子要点没有实现」就是这么来的）。
  现在用 `shared.indentedLines()`（保留行首空白再折算级别）。
  → 教训：凡是"按行首空白表达语义"的组件，都不能走会 trim 的行解析。

### 表格：列宽 / 行高 / 单元格格式（对齐 A4 + Excel 的单元格逻辑）

`table` 与四个表格预设（三线表 / 两列参数表 / 明细表 / 核对表）共用 `tableKit.tsx` 一份渲染内核。
**四个预设的 schema 与 `table` 完全相同**，只差默认的线条风格 / 数据 / 列宽 —— 它们是"数据模板"，不是独立功能。

**① 表格级属性**（作为"默认格式"，与 A4 编辑器 `js/30-tables.js` 同一套语义）

| 属性 | 填写方式 | 效果 |
|---|---|---|
| 行数 / 列数 | `行数` `列数` 输入框（**失焦或回车才生效**） | 把整张表改成这么多行/列（末尾补空、多出的截掉）；行数含表头行 |
| 列宽 | `20,50,30`（纯数字按百分比）或 `35mm,65mm`；**也可以直接拖表格竖线** | 写进 `<colgroup>` 的每个 `<col>`；没写到的列保持自动宽度 |
| 行高 | `9`（纯数字按毫米）或 `9mm` | **整表默认行高**：写到每个（未被单独覆盖的）单元格的 `height`；留空由内容撑开 |
| 按行行高 | **直接拖表格的行边界**（只改那一行） | `props.rowHeights = {"1":"15.2","3":"9"}`（键是**1 基行号**，含表头行时第 1 行就是表头）；面板「按行行高」可逐条清除 |
| 表题 | `表题` 文本（显示在表格**上方**） | 由表格自身渲染成真实 `<caption>` —— 与图片的图题同一做法，不再需要单独的"题注"组件 |
| 内边距 / 对齐 / 字号 / 表头底色 / 线条风格 / 斑马纹 | 属性面板 | 全表默认值 |
| 列宽自适应 | 单元格格式区里的按钮 | 按内容重算列宽并写回百分比（短列 13mm 保底） |

四个预设自带合适的列宽（如明细表 `8,30,30,12,20`）。

**② 拖动列边界改列宽**：选中表格后，列边界上出现 `col-resize` 手柄，
拖动只调**相邻两列**（每列 8mm 保底，合计不变）——与 A4 编辑器的表格列宽手柄同一套做法。
手柄挂在画布的**编辑器覆盖层**（`TableOverlay.tsx`，带 `no-print`），不写进文档。

**③ 单元格：选择 + 格式（Excel 逻辑）**

- **选择**：单击选一格；**按住拖拽框选一片矩形区域**（`useTableCellSelect.ts`）；Shift + 单击从锚点扩展；
  Ctrl/Cmd + 单击追加不相邻的格。选中的格子画蓝色选框，面板显示"选中 N 行 × M 列（第 x–y 行、第 a–b 列）"；
- **格式**：底色 / 字色 / 字号 / **加粗** / 左中右对齐 / 内边距 —— 改哪一项**立刻作用到选中的格子**
  （没有"应用"按钮，与 Excel 一致）；没被覆盖的项**沿用表格级默认**；「清除选中格式」退回默认；
- 数据存在表格的 `cellStyles` 属性（`{ "行,列": { 覆盖项 } }`，`行,列` 从 0 起、含表头时第 0 行是表头行），
  所以**会进导出、会打印**。

**④ 插入 / 删除行列（Excel 式，作用在选中区域上）**

「插入行 / 删除行 / 插入列 / 删除列」在**选中区域**处生效：选中 2 行就插/删 2 行（同 Excel）；
没选中单元格时按钮禁用并提示"先在画布上点一个单元格"。
插入/删除会**同步平移单元格格式与列宽**（给 B 列上色后左边插一列，颜色跟着内容右移，不会留在原坐标）。

> **两条边界（刻意的）**：
> ① **"选中了哪些单元格"是编辑器态**（`store.ui.tableCells`），**不进文档、不入导出、打印不显示** ——
>    自检里有两条断言把这条钉住（"单元格选择不写进文档" / "单元格格式是文档数据"）；
> ② 单元格格式**不是**"整表属性"：断言「加粗/居中只作用于选中格」同时验证同表另一格**没被改**。

### 画布浏览：两种模式两套方式（2026-09-23 用户确认）

| 模式 | 怎么翻看内容 | 标尺 |
|---|---|---|
| **文档模式** | **滚动条**（视口 `overflow:auto`）：滚轮 / 拖滚动条 / PageUp/Down；**不再**用空格或中键拖动画布 | 钉在视口顶部与左侧；刻度跟着**滚动量**走；长度按**全文内容总高**（多页时覆盖所有页，不再只画一页）；**纵向按页分段、每页从 0 读数**（见下） |
| **Web 模式** | **自由平移**（不变）：空格 + 拖拽 / 中键拖拽 / 滚轮，画布可拖出可视区、不夹边界 | 同样钉在视口边缘；刻度跟着**平移量**走 |

**标尺读数与步长（2026-09-24 用户反馈后改）**：

- **纵向标尺逐页分段、每页从 0 开始**：以前是"整篇一根连续标尺"，26 页就要一路数到 **7000+mm**，数字越数越长、
  越挤；现在每页都显示 `0mm … 页高`（A4 = 0…290mm 一带），页与页之间留空。
  实现：`Canvas` 实测每一页在内容里的区间（`[data-paper]` 的实测位置，未缩放 px）→ 传给 `Ruler` 的 `spans`。
  实测对齐：9 页文档的页顶 `0/1137/2274/…/9096` 与刻度里 9 个「0mm」的位置**逐一对上**。
- **横向标尺的 0 跟纸张左边缘对齐**（2026-09-24 修）：内容比视口窄时 `margin:0 auto` 会把它**居中**，
  刻度必须把这个左内缩算进去 —— 以前从"视口左边缘"起算，于是顶部比例尺整整差一个 auto margin
  （实测：纸张左边缘 x=403，标尺 0mm 却在 x=274，偏 **−128px**）。实现：量 `[data-pan-layer]` 的 `offsetLeft`
  作为内缩（视口尺寸变化时用 `ResizeObserver` 重算），刻度层 `transform: translateX(内缩 − 滚动量)`。
  实测三种情形都对：居中 **+1px**、放大到 180% 未滚动 **0px**、横向滚到 200px 后 **0px**。
- **步长随缩放自适应**：带字大格至少留 34px（`LABEL_MIN_PX`），不够就自动放大到 20/50/100/200/500mm
  （Web 模式 200/500/1000/2000px）；小刻度少于 7px 时干脆不画，避免糊成一条。
  实测：100% → 大格 10mm；40% → 大格 50mm；76% → 20mm。当前大格写在 `[data-ruler-major]` 上，便于自检核对。

- **外部写入自动跟随**：MCP（或任何外部通道）把文档写长、写到下一页时，只要用户当前就在**底部附近**，
  预览会自动滚到新的底部（不会"还在写下一页、画布却停在旧位置"）；用户正在看中间内容时**不抢视线**。
- Ctrl/Cmd + 滚轮在两种模式下都是"以指针/视野中心为锚点缩放"（滚动量与平移量分别参与计算）；
  文档模式的普通滚轮交给原生滚动，Web 模式才转成平移。
- ⚠ 踩过的坑：视口 DOM 在两种模式间**复用**，而 `overflow:hidden` 的容器也会保留 `scrollTop` ——
  从文档模式切到 Web 模式时必须清零视口的 `scrollTop/scrollLeft`，否则 Web 画布一上来就纵向偏移。
- ⚠ 踩过的坑（用户 2026-09-23 报「切回文档模式 A4 偏移到预览框 0,0」）：画布的"实测内容尺寸"
  必须按**模式**归属。`contentW = max(实测宽, 纸张宽)`，而被测量元素自身的宽度又是 `contentW` 赋的 ——
  从 Web 模式带回的实测宽（画布 1440px）会把这个式子**自我锁定**在 1440，`margin:0 auto` 失效，
  A4 就贴在视口左边回不来了。修法：`useScaledBox(…, scope=mode)`，换模式即作废（本次渲染按纸张
  尺寸兜底，紧接着布局阶段量真实值）。自检里「文档 ↔ Web 来回切模式」一条就守这个。

### 画布缩放（只缩放画布，不缩放编辑器界面）

- **Ctrl/Cmd + 滚轮**：接管该手势（`preventDefault`），只缩放画布预览——不会像浏览器缩放那样把菜单栏/面板一起放大；
- 画布右下角**悬浮缩放控件**：`− 100% ＋ | 适应宽度 | 100%`（跟随浅色/深色主题）；
- 工具栏 / 视图菜单 / Ctrl± / Ctrl+0 同样只作用于画布；**默认缩放 100%**。

## 六、组件开发：加组件只动它自己的文件

**内置组件：注册表由目录自动发现，不维护清单。** `registry/components/index.ts` 用
`import.meta.glob('./**/*.tsx', { eager: true })` 把目录下的文件全部静态导入，
再挑出"看起来是组件定义"的导出（`type` 是字符串 + `render` 是函数）自动注册。

- 加/删/改一个组件 = **只动它自己的 `.tsx`**，不需要改 `index.ts`（以前要在这里加 import 和数组项）；
- 工具模块（如 `tableKit.tsx`）不会被误注册 —— 靠"是不是组件定义"判定，不需要维护排除名单；
  想彻底跳过某个文件，让文件名以 `_` 开头即可；
- 同一分类内的面板顺序 = **文件路径字母序**；要固定顺序就给文件名加数字前缀（如 `10-table.tsx`）；
- 每个组件文件导出 `export const xxxComponent: ComponentDefinition = {...}`（照抄邻居即可）。
- 自检断言「组件注册表由目录自动发现」会核对：目录发现数 == 注册表内建数（防止有人又回去手写清单）。

**外部组件（热加载，改完不用构建）**：

两条路，按需要选：

| 方式 | 文件位置 | 是否要构建 | 适合 |
|---|---|---|---|
| **外部组件（热加载）** | `public/组件/*.js`（普通 JS，无需 TS） | **不用**：改完保存 → 编辑器里点「重载外部组件」 | 加常用组件、改文案/样式/属性、给别人临时加组件 |
| 内置组件 | `src/registry/components/**/*.tsx` | 要（`npm run build`；开发时 `npm run dev` 有 HMR） | 参与工程长期维护、需要类型检查的组件 |

**加一个外部组件（3 步）**

1. 在 `public/组件/` 下新建 `我的组件.js`，照抄现成例子（`提示条.js` / `参数对比卡.js` / `免责声明.js`）；
2. 文件里调用 `window.EditorKit.register({...})` 注册组件定义（`type/label/category/supportedModes/icon/defaultProps/propSchema/render`）；
3. 回到编辑器打开 **首选项 → 组件箱 → 重载**（2026-09-24 起这是唯一入口：帮助菜单与组件箱底部的按钮都已收进去）→ 左侧面板立刻出现新组件，**不需要 npm run build、不需要重启服务**。

`window.EditorKit` 提供（定义见 `src/registry/live.ts`）：

| 能力 | 说明 |
|---|---|
| `React` | React 本体，用 `React.createElement` 写渲染 |
| `register(def)` | 注册组件；同名 type 会**先卸载再注册**，所以改完重载即生效 |
| `fontProps / boxProps / fontSizeProp / …` | **与内置组件同一套通用属性片段**（属性面板行为完全一致） |
| `defaultsOf(schema)` / `defaultFrameOf(w,h)` | 由 schema 推导 defaultProps；默认位置尺寸 |
| `boxStyle / typographyStyle / alignOf / spacingCss / edgeCss` | 属性 → CSS |
| `asString / asNumber / asBool / asEnum / lines / rows` | 取值守卫（与内置同源） |
| `icon('Megaphone')` | 按名字取图标（白名单见 `live.ts`，未命中会退回默认图标并记 warn） |

**它是怎么生效的**

- 清单：编辑器请求 `/__components` 拿文件列表（Vite dev 里由 `vite.config.ts` 的中间件提供；启动器里由 `启动编辑器.py` 提供；都没有时退回静态 `public/组件/_manifest.json`）；
- 加载：对每个文件做**带时间戳的动态 import**（`?t=…`，绕开浏览器缓存），文件执行时自注册；
- 服务：启动器**直接服务 `public/组件/`**（不是 dist 里的副本），所以「改文件 → 点重载」这条链路上没有任何构建步骤；
  ⚠ 因此 `dist/组件/` 只是**构建时的复制副本**，运行时不会被服务 —— **改外部组件请改 `public/组件/`**，
  改 `dist/组件/` 无效且下次构建会被覆盖；
- 失败可见：某个文件加载失败会把**文件名 + 错误**写进日志，在 帮助 → 诊断信息 里能看到，不会静默消失。

> ⚠ **两道安全网**（外部组件写错不会把编辑器搞白屏）：
> ① 注册时校验——没有 `type` / `render` 的定义会被拒绝并记 `error`；
> ② **节点级错误边界**——某个组件 `render` 抛错时，只把**该节点**降级成一块红色提示并记 `error` 日志，
>    同页其它节点照常显示（`NodeView.tsx` 的 `NodeErrorBoundary`）。
> 这条正是被自检的"属性面板遍历全部组件"逼出来的：示例外部组件 `参数对比卡.js` 曾把辅助函数当组件类型
> 传给 `createElement`（`createElement(head, …)`），render 抛错后**整个应用被顶层错误边界替换成错误页**——
> 画布、面板全部消失。现已修复组件本身，并加了节点级隔离与对应断言。

> 已实测：`public/组件/提示条.js` 改一个字符串，服务端返回内容立刻变化（3202 → 3217 B），**未构建、未重启**；自检里也有"外部组件已热加载 / 重载幂等"两三条断言。

### 导出通道一览（界面 与 MCP 同源）

排版内核只有一份，导出能力也**只有一份** —— 界面菜单与 `mcp__editor__export_*` 走同一批实现（Live 桥接里的 `export.*` 路由）：

| 产物 | 界面入口 | MCP 工具 | 说明 |
|---|---|---|---|
| **HTML** | 文件 → 导出 HTML | `export.html` | 可独立打开的整页 HTML（含 `@page`）；给 `path` 就落盘到工作区 |
| **Word .docx** | 文件 → 导出 Word（.docx） | `export.docx` | **真 OOXML**（自写 STORE ZIP，无第三方依赖）；Live 返回 base64，MCP 侧按 `path` 落盘，缺省用文档标题命名 |
| **PDF** | 文件 → 打印 / 另存为 PDF | `export.pdf` | PDF 由浏览器打印通道产出，**MCP 拿不到字节** —— 该工具只把这一步提示清楚（不假装导出了文件） |
| **.editor.json** | 文件 → 导出 JSON | `export.json` | 编辑器文档存档，可再导入编辑 |
| **React/TSX** | 文件 → 导出 React | `export.react` | 给开发同学复用的代码 |

> ★2026-09-24 补：`export.docx` 是**新挂上 MCP 的**。以前 .docx 只有界面菜单能导，于是"要一份 docx"只能绕道 Python 产线 ——
> 用户指出这不对：**本产品自己就支持导出 html 与 docx**，要独立文件就走上面的 `export_*`，不是换产线。
> 自检里有两条断言直接调 Live 路由验证：`export.docx` 返回的 base64 是**合法 ZIP（真 OOXML）**、`export.html` 带 `@page` 与 `data-node-type`。

### MCP 桥接的状态显示（2026-09-24 修）

帮助菜单的「MCP 桥接：…」文案以前有两个毛病：① `state === 'off'` 同时表示"没开启"和"开了但没连上"，于是点完开关还写「未开启」；
② 桥接状态是模块级变量、**没有订阅**，弹窗说已开启之后 React 不重渲染，菜单一直是旧的。现在：
`useBridgeSummary()`（`useSyncExternalStore` 订阅）把四种状态分开说 —— `未开启` / `连接中…` / `连接中…（第 N 次重试）` / `已连接（N 个外部组件）`；
点开关后**等状态落定再弹窗**（连上才说已连接；没连上给出 `ws://…`、上次错误与三条排查办法），不再抢着报成功。
诊断口径：向 `ws://127.0.0.1:37650/bridge` 发 `bridge.hello` 会收到
`{name:'editor-mcp-hub', editors:N, editorVersion, clients:M}` —— **`editors: 0` 就是"一个编辑器都没接上"**。

## 八、日志与诊断（出问题怎么定位）

日志是**四层**，落盘位置遵循常见软件的习惯：**运行目录下的 `logs/`**（即 `web-editor/logs/`）。

| 层 | 内容 | 位置 / 用途 |
|---|---|---|
| **运行目录文件**（推荐） | 前端日志按天追加 | `logs/editor-YYYY-MM-DD.log` —— 由**启动器**的 `/__log` 写入；服务自身的访问/错误写 `logs/server-*.log`；自检结果写 `logs/check-*.log`；诊断报告写 `logs/diagnostic-*.log` |
| console | 按级别输出（dev 默认 `debug`，prod 默认 `warn`，可用 `?log=` 覆盖） | 开发时即时看 |
| 内存环形缓冲 | **全量**最近 500 条（含 debug），可订阅 | 面板里查看/下载 |
| localStorage `visual-editor-log-v1` | 尾部 200 条（warn/error 即时落盘 + 关闭页面时） | **兜底**：直接双击 `dist/index.html`（file://）或换用别的静态服务器时没有 `/__log` 接口，就只在这里；诊断报告会如实标注"未启用" |

> **为什么需要启动器**：浏览器没有文件系统权限，前端无法自己写运行目录 ——
> 所以落盘由本地服务（`启动编辑器.py`）完成：前端 `POST /__log`，服务按天追加到 `logs/`；
> `GET /__loginfo` 返回目录与文件大小，诊断报告的【日志落盘】段就显示这个路径。
> 想手动导出也随时可用：菜单 **帮助 → 保存诊断报告到运行目录**（无接口时改为复制/下载）、
> **帮助 → 下载日志文件**。

记录了什么：

- **启动信息**：地址、视口、像素比、日志级别、恢复的历史日志条数；
- **动作意图**：每个会改文档的 action 记一条 `[action] xxx`（如 `addComponent {type,parentId,mode}`、`importJSON {bytes}`、`setMode {from,to}`）；
- **变更效果**：任何文档变更都会记 `mode / 文档组件数 / Web顶层数 / 选中数 / 历史深度 / 是否被防抖合并`；
- **性能**：`commit` 等关键路径超过阈值记 `warn`（带耗时 ms）；
- **错误**：`window.onerror`、`unhandledrejection`、以及 **React 错误边界**捕获的渲染错误（附错误栈 + 组件栈）；
- **数据结构异常**：如 `importJSON` 结构不合法会记 `error` 并列出实际键名。

怎么看：

1. 菜单 **帮助 → 诊断信息**（或 `?diag=1`）：四块状态（运行环境 / 编辑器状态 / 组件注册表 / 当前模式结构）+ 日志列表（可按级别过滤、可切换输出级别）+ 按钮「复制完整诊断报告 / 刷新 / 下载日志 / 清空」。
2. 菜单 **帮助 → 下载日志文件**：直接导出 `.txt`。
3. 控制台里 `__EDITOR_LOG__`：`__EDITOR_LOG__.entries()` / `.dump()` 可随时取。

诊断报告长这样（4 段 + 日志尾部，可直接粘给他人）：

```
================ 可视化编辑器 诊断报告 ================
【运行环境】   时间/地址/浏览器/视口/语言/在线
【编辑器状态】 模式/标题/缩放/纸张/设备/两模式组件数/选中数/历史深度/剪贴板/面板状态
【组件注册表】 组件总数/两模式可用数/容器数/纸张与设备预设数
【当前模式结构】节点数/最大嵌套深度/各类型数量
【日志（尾部）】带时间戳、级别、作用域、结构化数据
================ 报告结束 ================
```

> 出问题时**先复制这份报告**（菜单 帮助 → 诊断信息 → 复制完整诊断报告），里面已经包含复现所需的绝大部分信息。

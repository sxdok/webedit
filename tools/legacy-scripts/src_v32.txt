客户现状
控制系统：多 PLC 架构。主控 PLC 控制设备层，另有一台专用于对外数据交互的 PLC，机械臂各带控制；核心为西门子 S7-1518（1500 系列）。
软件系统：无上位调度系统，各 PLC 独立运行，产线物料配送尚未接入统一的车辆调度与设备对接系统。
技术能力：PLC 程序完全自主编写、可按需改造；机械臂与 PLC 完整交互；现场已有看板，仅与设备内部对接。
现场条件：智慧舱内为单向单通道，仅入口 A 进、出口 B 出；客户不设双车道，通道净宽约 1.5 m。

核心需求概括
通过一台专用数据交互 PLC 与 AGV 系统交互：AGV 只需按托盘号 1–10 完成空托盘回收与满料托盘配送，不识别托盘内物料。空托盘拉走、对应编号托盘送到工位并反馈到位，即完成一次作业。
系统范围界定
本项目交付 AGV 车辆 + RCS 车辆调度系统 + WCS 设备对接系统 + 现场调试，一体交付。
不含 WMS 仓储管理系统。本项目为产线工位级物料配送，无入库、出库、库存、批次等仓储业务，库位与托盘状态管理由 WCS 承担，不引入 WMS。
换型 / 换产不在本次范围内。系统只保证"托盘号 ↔ 设备内上料区（工位号）"严格对应，不参与换型动作。
成品下线不在本次范围内。成品由设备自带流程（进包 → 装袋 → 装箱 → 码垛）处理；如需纳入 AGV 转运，另行评估。
通信方式：目前 Modbus-TCP 或 S7 都支持。

完整配送流程
舱内为单向单通道，入口 A 进、出口 B 出，车辆不可逆行。一次叫料由两台车按严格顺序流水完成，形成"空料框移出 → 补料确认 → 满料框补入"的完整闭环。
作业动作链（以 3 号工位为例）
设备 3 号工位物料耗尽，主控 PLC 发出叫料信号，WCS 接收后由 RCS 生成"回收 + 配送"两个子任务。
第一辆车（空车）行至 A 门外，向 WCS 申请进入；WCS 通知 PLC，PLC 确认机械臂停止作业后允许进入，自动门开启。
空车从入口 A 进舱，沿单向通道行至 3 号工位，顶起空托盘（连支架整体）。
空车继续前行，从出口 B 出舱，将空托盘送至暂存区 S3 位放下，该位状态置为"待补料"。
人工在暂存区为 S3 空托盘补料，完成后通过 PDA / 移动端扫码或点选托盘号确认，该托盘状态置为"可用"。
系统生成低优先级闲时转运任务，空闲车辆将托盘由暂存位 S3 移至备料位 B3（满料待送）。
第二辆车（满料）从备料位 B3 顶起满料托盘，行至 A 门外申请进入；此时 3 号工位已腾空， PLC 给出允许进入信号。
满料车从入口 A 进舱，行至 3 号工位就位放下满料托盘，向 WCS / PLC 反馈"放料到位"。
满料车继续前行，从出口 B 出舱，任务完成，车辆转为待命或接受下一任务。
一次完整循环必须"先回收、后配送"：满料车若先于空车到达工位，将无处放料且无法退出（通道不可逆行）。系统以子任务依赖强制保证——回收子任务完成并腾空工位后，才释放配送子任务的放料许可。

总体方案架构
系统由 RCS 车辆调度与 WCS 设备对接两套独立系统构成，分别承担车辆调度与设备信号交互。
系统组成
针对现场仅有 PLC、无软件系统的现状，构建 RCS（车辆调度系统）+ WCS（设备对接系统）+ AGV 执行层 的软件体系，与客户数据交互 PLC 通过 Modbus-TCP 通讯。系统部署在设备工控机提供的虚拟服务器上。

WCS 与 RCS 是两套独立系统：AGV 车体嵌入式控制（激光导航）负责车体自身定位与运动，RCS负责车辆调度，WCS 负责与 PLC、自动门等设备硬件的信号交互。RCS 向 WCS 下发搬运任务时，仅需传递起始点与终点两个位置信息；任务过程中 WCS 与 PLC 的安全交互由 WCS 独立完成。

库位编码与绑定关系
绑定规则：N 号托盘固定使用暂存位 S_N 与备料位 B_N。托盘流转路径为"设备 W_N → 暂存位 S_N（空盘）→ 人工备料、PDA 确认 → 备料位 B_N（满料）→ 叫料送回设备 W_N"。由于库位 与托盘固定绑定，任一时刻各库位状态唯一、互不侵占，从库位模型上避免"暂存区满了、空盘无处卸放"的问题。
系统只认托盘号，不认物料。无论托盘内装载何种物料，系统均按托盘号执行配送与回收，不做物料校验，仅维护托盘身份与库位映射，大幅简化逻辑，避免误判与停机。

WCS 与设备对接协议
WCS 与客户数据交互 PLC 通过 Modbus-TCP 交互。本章说明通讯方式与四种对接时序；具体寄存器点位表不在本方案内，另行以《WCS 对接协议》文档提供，双方确认后按点位表实施。
通讯方式
点位与寄存器映射由配套《WCS 对接协议》文档给出，本方案不重复列示。
对接时序一	申请 + 离开（上层下发任务）
适用于任务由上层系统下发，WCS 只负责与设备做安全交互的场景。任务时序：
上层下发 AGV 取 / 送料搬运任务，调度 AGV 移动到 PLC 点位前等待点。
WCS 通知 PLC 点位申请取 / 送料（写 0001 / 0004）。
PLC 判断点位状态安全，给出允许取 / 送料（点位状态 0001 / 0003）。
AGV 进入点位取送料，完成后退出到等待点。
WCS 通知 PLC 点位取 / 送料离开（写 0003 / 0006）。
PLC 清空允许取 / 送料（点位状态 0000），WCS 清空取 / 送料离开（写 0000）。
对接时序二	申请 + 离开（PLC 下发任务）
适用于任务由 PLC 点位给出的场景，WCS 轮询检测到任务信号后通知上层生成搬运任务。任务时序：
PLC 点位给出取 / 送料任务（任务信号 0001 / 0002）。
WCS 轮询检测到后，通知上层下发 AGV 取 / 送料搬运任务。
AGV 移动到 PLC 点位前等待点，WCS 通知 PLC 点位申请取 / 送料（写 0001 / 0004）。
PLC 判断点位状态安全，给出允许取 / 送料（任务信号 0000、点位状态 0001 / 0003）。
AGV 进入点位取送料，完成后退出到等待点，WCS 通知 PLC 点位取 / 送料离开（写 0003 /
0006）。
PLC 清空允许取 / 送料（点位状态 0000），WCS 清空取 / 送料离开（写 0000）。
对接时序三	申请 + 到达 + 离开（上层下发任务）
在"申请 + 离开"基础上增加"到达"确认环节，适用于设备需在 AGV 到位后才开始作业的场景。

任务时序：
上层下发搬运任务，AGV 移动到 PLC 点位前等待点，WCS 通知 PLC 申请取 / 送料（写 0001 /
0004）。
PLC 判断安全，给出允许取 / 送料进入（点位状态 0001 / 0003）。
AGV 移动到点位，WCS 通知 PLC 取 / 送料到达（写 0002 / 0005）。
PLC 开始作业，完成后给出允许取 / 送料离开（点位状态 0002 / 0004）。
AGV 移动到点位外等待点，WCS 通知 PLC 取 / 送料离开（写 0003 / 0006）。
PLC 清空允许信号（点位状态 0000），WCS 清空取 / 送料离开（写 0000）。
对接时序四	申请 + 到达 + 离开（PLC 下发任务） 任务由 PLC 点位给出，且设备需在 AGV 到位后才开始作业。任务时序：
PLC 点位给出取 / 送料任务（任务信号 0001 / 0002）。
WCS 轮询检测到后，通知上层下发 AGV 搬运任务。
AGV 移动到点位前等待点，WCS 通知 PLC 申请取 / 送料（写 0001 / 0004）。
PLC 判断安全，给出允许取 / 送料进入（任务信号 0000、点位状态 0001 / 0003）。
AGV 移动到点位，WCS 通知 PLC 取 / 送料到达（写 0002 / 0005）。
PLC 开始作业，完成后给出允许取 / 送料离开（点位状态 0002 / 0004）。
AGV 移动到点位外等待点，WCS 通知 PLC 取 / 送料离开（写 0003 / 0006）。
PLC 清空允许信号（点位状态 0000），WCS 清空取 / 送料离开（写 0000）。
四种时序均按客户实际要求选用。实施前需明确：任务由上层还是 PLC 下发；是否需要"到达"确认环节；是否需要 WCS 在任务上报前读取 PLC 参数（如容器类型）、或向 PLC 透传上层参数。确定后锁定其中一种，其余作为备 选；锁定结果写入《WCS 对接协议》点位表。
机械臂与自动门对接
设备层仅保留机械臂与自动门两个核心对接对象，其余设备信号不纳入本次对接范围。
机械臂
AGV 进入设备前，必须确认机械臂已停止作业；PLC 给出"允许进入 / 禁止进入"信号。
机械臂动作期间返回"禁止进入"，车辆在门外安全位等待，不进入舱内。
车辆在设备内部期间持续输出"AGV 在舱内"状态，供设备侧做机械臂动作闭锁参考。
待确认：允许进入信号是全局一个（4 台机械臂全部就绪），还是按工位分区。分区可显著缩短车辆等待时间。
自动门
设备设一进一出两个自动门，AGV 到门口请求开门，作业完成并退出后请求关门。
门控支持两种模式：由 WCS 直接控制开关门，或由 PLC 控制、WCS 只发请求信号。
门未开到位，AGV 不启动进入动作；关门以"车辆完全退出"为前提。
待确认：两个门能否同时开启（可同时开启是实现"前车出舱、后车跟进"流水作业的前提）。

异常与通信保护
心跳保护：WCS 每隔 1 秒交替写入心跳值；PLC 侧检测心跳值长时间未变化即判通信异常。通信恢复后按任务状态续跑。
申请超时：WCS 发出申请后，PLC 在约定时间内未给出允许信号，车辆退回点位外等待点并上报。
点位异常：PLC 侧点位存在故障（设备未停、安全门未闭合等）时不给出允许进入信号，车辆门外等待。
安全原则：通信中断时车辆原地安全停止、不动作，不进入任何未获许可的点位。

调度逻辑与关键业务流程
本章说明单向流水线的作业编排、检修处置与补料闭环。
单向流水线作业模式
舱内为单向单通道（A 进 B 出、不可逆行），不存在对向交会。一次叫料拆为"回收 + 配送"两个子任务，由两台车按严格先后顺序流水执行：前车取走空托盘继续前行出 B 口时，后车已可跟进 A 口，形成流水线。

流水收益：车 2 在车 1 出舱前即可跟进进舱，两车在通道内同向行驶、保持安全跟车间距，单工位
周转由单车串行的约 160 ~ 190 s 缩短至约 70 ~ 90 s（示例估算，按 36 m 舱体、1.0 ~ 1.2 m/s车速），最终以现场实测与联调为准。
约束：
顺序不可颠倒。必须先回收、后配送；满料车若先于空车到达工位，将无处放料且无法退出。系统以子任务依赖强制保证。
跟车间距。通道内同向多车需保持安全间距（建议 ≥ 2 m，最终按车辆制动距离核定），系统按"前车位置 + 安全距离"动态控制后车速度。
单向不可逆。车辆一旦进舱只能向前至 B 口出舱，中途不可后退、不可掉头；派车前必须确认任务完整可行。
舱内异常处置（单向通道特有风险）：
低速倒车退出。车辆保留低速反向行驶能力，仅在故障应急时启用，退出 A 口（通道宽度允许性现场核定）。
人工介入。现场人员进入舱内处置，需设备停机、机械臂锁定、安全确认。
任务重排。系统暂停 A 口进车，已进舱车辆继续前行出 B 口，避免连锁堵塞。
检修临时移出 / 复位流程
设备需检修时，操作员在系统界面勾选需移出的工位号（如 4、5、6）。

点击"批量移出"，系统自动生成移出任务链，AGV 依次将对应托盘搬运至设备旁的临时移出区。
移出完成后通道放开，人员进入检修。
检修完毕，操作员点击"复位"，系统按记录的原始位置将托盘逐一还回原工位。
全过程为人工触发，系统不自动执行，避免误动作。
补料闭环
空托盘入暂存区。AGV 从设备取回空盘放入 S 位。
看板提示。暂存区看板显示"X 号待补料"。
人工备料。人员将物料上到托盘并点击确认。
转备料位。空闲车辆将该托盘移至备料区对应 B 位（低优先级闲时任务）。
状态更新。该托盘置为"可用"，等待叫料。
补料及时性属现场管理范畴，系统提供提醒与状态记录，不执行自动补料。人车分流：人工在暂存区备料作业，AGV 在备料区取料进舱，互不干扰。

测算模型

地面与环境要求
平整度：运行区域需为平地，提供专门的地面平整度标准文件。
坡度：爬坡能力 ≤ 3°，超出限值需专项评估。
